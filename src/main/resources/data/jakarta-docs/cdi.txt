Jakarta Contexts and Dependency Injection (CDI) 4.1

CDI is the backbone of Jakarta EE applications, providing a typesafe dependency injection framework with container-managed lifecycles.

Core Concepts:
- Beans: CDI beans are Java classes managed by the container. A bean has a lifecycle, scope, and can be injected into other beans.
- Scopes: CDI defines several built-in scopes. @RequestScoped lives for a single HTTP request. @SessionScoped lives for an HTTP session. @ApplicationScoped lives for the entire application lifecycle. @Dependent is the default pseudo-scope where a new instance is created each time it is injected.
- Injection: Use @Inject to obtain bean instances. CDI resolves types automatically.
- Qualifiers: Use custom annotations with @Qualifier to disambiguate between multiple beans of the same type.
- Producers: Methods annotated with @Produces create beans from non-default constructors or complex initialization logic.
- Events: CDI provides a synchronous and asynchronous event system. Fire events with Event.fire() and observe them with @Observes.

CDI 4.1 New Features:
- Build Compatible Extensions: A new extension model that works in both full CDI and CDI Lite environments, using annotations instead of the SPI.
- Improved interceptor binding support.
- Better alignment with Jakarta Core Profile.

Integration with Other Jakarta Specs:
CDI integrates with nearly every Jakarta EE specification. JPA entities can be CDI beans with @Dependent scope. JAX-RS resources support constructor injection. Jakarta Concurrency uses CDI for managed executor configuration. MicroProfile Config integrates via CDI producers.
