Jakarta Persistence (JPA) 3.2

JPA is the standard API for object-relational mapping in Jakarta EE, mapping Java objects to database tables.

Core Concepts:
- Entities: A class annotated with @Entity maps to a database table. Each entity instance represents a row.
- Entity Manager: The EntityManager interface provides operations for persisting, finding, querying, and removing entities. Inject it with @PersistenceContext.
- Persistence Units: Defined in persistence.xml, a persistence unit configures the data source, entity classes, and JPA provider settings.
- Transactions: JPA operations typically run within Jakarta Transactions (@Transactional or container-managed transactions).

Key Annotations:
- @Entity: Marks a class as a JPA entity.
- @Id: Defines the primary key field.
- @GeneratedValue: Configures auto-generation for primary keys.
- @Column: Customizes column mapping (name, length, nullable).
- @Table: Specifies the database table name.
- @OneToMany, @ManyToOne, @ManyToMany: Define relationships between entities.
- @Embedded / @Embeddable: Compose value types into entities.

JPQL (Jakarta Persistence Query Language):
A SQL-like query language that operates on entities and their fields rather than tables and columns. Example: "SELECT t FROM ConferenceTalk t WHERE t.track = :track ORDER BY t.timeSlot".

JPA 3.2 Improvements:
- Better support for Java records as embeddables.
- Enhanced Criteria API with more fluent APIs.
- Improved batch processing performance.
- UUID support as primary key type.

Best Practices:
Use @PersistenceContext to inject EntityManager rather than creating it manually. Keep entities as POJOs with minimal business logic. Use DTOs or projections for read-only queries to avoid loading unnecessary data.
